## Execution contract to qualify

Inventory, normalization, dry-run, and the CLI's refusal of live dispatch must remain available. Live execution requires an approved isolated worker and supervisor, registered versioned HTTP, GraphQL and bounded WebSocket adapters, and explicit egress authority. The bounded envelope must bind normalized non-secret request data, session and role bindings, destination policy, budgets, immutable approval, plan and request digests, and credential references. Resolve credentials only after exact approval. Bump executable operation contracts; legacy executable operations lacking the envelope or explicit egress must be rejected. Historical evidence remains readable and is not execution authority.

The typed Web API mediator admits only exact-approved GET, HEAD, OPTIONS, POST, PUT, PATCH and DELETE. Reject CONNECT, TRACE, arbitrary TCP, unrestricted upgrades and raw sockets. Revalidate DNS, scope, TLS, method, redirect, headers, body and budgets at every transition; remove credentials on cross-origin redirects. Plaintext is limited to disposable loopback laboratories; production requires HTTPS or WSS. GraphQL permits bounded GET/POST queries and variables, not subscriptions. WebSocket permits bounded text only; binary, compression, extensions, fragmentation, arbitrary subprotocols and oversized messages are unsupported. Unsupported features must be reported, not silently executed.

The Linux isolation qualification must demonstrate denial of raw sockets, approval-store and administrative-key access, unrelated credentials and outside-workspace files. Evidence must capture application context, provenance, digests, limits, redirect decisions, unsupported features and ownership-aware cleanup receipts with credential, cookie, authorization and sensitive-body redaction. A timeout, cancellation or ambiguous post-dispatch outcome requires reconciliation and fresh authorization, not automatic replay. A cleanup receipt describes observed cleanup; it does not prove reversal of remote effects.

## Qualification and closure

Run focused envelope strictness, session/role, redaction, mismatch and legacy-rejection checks; redirect, DNS, host, userinfo, metadata, cross-origin, TLS, timeout, cancellation and budget checks; disposable REST/GraphQL/WS/WSS sessions; sandbox denial and cleanup cases; and independent approval expiry, revocation, scope, double-spend, restart and ambiguous-retry cases. Run the focused acceptance gate, package gate, Linux isolation gate, installed/exported package checks and `make check`, recording exact revision, commands, environment, outcomes and cleanup. Missing tests, skips or unsupported platforms remain explicit limitations, not passing evidence.

Hosted CPython 3.15 checks and human security review of the exact integrated revision remain separate closure gates. Local loopback or synthetic approval tests do not establish an independently administered production approval service, production worker isolation, or production-provider behavior. A platform without the required isolation cannot enable live execution on the strength of a portable package check.
