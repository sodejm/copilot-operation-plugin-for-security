# AI asset inventory contract

`cops.evidence.ai_inventory` imports a bounded, versioned evidence projection. It never makes a network request, invokes a tool, starts discovery, or infers assessment authorization.

Documents use `cops.ai-inventory/v1`. Assets are source-and-tenant qualified and may be agents, agent runs, model endpoints, MCP servers/tools, retrieval/memory/cache stores, service identities or destinations. Provider and tenant values reject `/` so their namespace delimiter cannot collide. Relationships are observed or declared; `parent_child` represents observed run lineage. Every asset and relationship has selected-record provenance and completeness. Assets may carry bounded `permissions` and `scopes` arrays. Prompts, trace payloads, inputs, outputs and tool arguments have no contract field and are rejected.

The importer validates a complete document before a registry retains it. Unsupported versions, malformed references, conflicting identities and size/count limits are content-free `InventoryError` diagnostics. Comparison returns deterministic added, removed, changed and unknown facts, plus explicit permission and scope changes, retaining declared or incomplete edges as uncertainty. A report includes selected trust-boundary relationships and bounded agent-or-run-to-destination paths with support and completeness. It separately reports only ordered untrusted-document to agent/run to privileged-MCP-tool to destination paths, preserving each asset's explicit trust level. Report and comparison revalidate public snapshot mappings and use an engagement-bound restricted reference. A source reconciles an agent to an external identity only through a provenance-backed `identity_links` record with a sponsor, alias, merge or split rationale; it never merges source records. The import and comparison-result JSON Schemas and representative fixtures are maintained under `cops/evidence/schemas/` and `tests/fixtures/`.

The offline LangSmith adapter accepts only `cops.langsmith-query-runs/v2`, a COPS wrapper around one selected-field response from `POST /api/v2/runs/query` in the official LangSmith API reference at `https://eu.api.smith.langchain.com/redoc`. The request selects the provider enum values `ID`, `NAME`, `RUN_TYPE`, `START_TIME`, `PARENT_RUN_IDS`, `TRACE_ID` and `PROJECT_ID`; the response projection contains their lowercase keys in `items`, plus `next_cursor`, and orders `parent_run_ids` from trace root to direct parent. The wrapper metadata is COPS-owned, so this contract is not a literal raw API export. It rejects other response fields so inputs, outputs, events, errors, metadata, manifests, attachments and other trace content cannot enter the inventory. It maps chain, LLM/embedding, retriever and tool records to tenant-qualified generic `agent_run` assets, retaining the run type in each identity. Parent-child edges exist only for present parents. LLM/embedding child records also produce `delegation` edges, and tool child records produce `tool_invocation` edges; these operation edges do not assert a provider resource, MCP registration, privilege, authorization or target identity. Missing parents, pagination and unavailable owner, permission and tool-effect facts remain explicit unknowns. A non-null cursor makes the snapshot partial without retaining the cursor. Duplicate equal records collapse; conflicting duplicates, present parent lineages, cycles, unsupported run types, versions and shapes fail closed. Export of an inventory report requires the concrete `ExportBoundary` and a caller-provided sink registered for the `report` destination; another boundary type, a mismatched destination or boundary refusal fails closed without fallback output.
